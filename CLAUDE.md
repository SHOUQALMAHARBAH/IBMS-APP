# CLAUDE.md — ibms-app

This is the first IBMS engineering repo. **Standards, mandatory rules, domain
knowledge, and architecture decisions live in `ibms-brain` (imported above via git
submodule at `ibms-brain/`), not here** — `ibms-brain/meta/lex/` (mandatory),
`ibms-brain/meta/context/` (domain knowledge), `ibms-brain/meta/designs/` (why decisions
were made). Read the relevant `meta/context/` file before touching an area, and the
`meta/lex/` rules before any non-trivial change — most of them (money-decimal-jod,
workflow-state-transitions, maker-checker-segregation, sensitive-data-handling,
pdpl-sla-timers) apply the moment real domain code lands here, which it has not yet.

| 2026-09-11 | **Multi-tenancy Phase 2 step 8 — PostgreSQL Row-Level Security, the independent second layer.** Spec §1 asks for two layers that fail independently; step 7 built the first, this is the second. **118 policies**, one per tenant-scoped table, keyed to `current_setting('app.current_org_id', true)` with `WITH CHECK` mirroring `USING` so writes are governed too. The table list is derived from `schema.prisma` by the same rule the runtime extension uses, so the policies cannot cover a different set of tables than the application layer does. **The detail that silently defeats all of it**: Postgres exempts a table's OWNER from its own policies. The tables are owned by `ibms`, which also runs migrations and the seed — so the API now connects as **`ibms_app`**, a role that owns nothing, has no SUPERUSER and no BYPASSRLS, and holds only SELECT/INSERT/UPDATE/DELETE. `npm run db:provision-app-role` creates it (deliberately NOT a migration: a role is cluster-level, needs CREATEROLE, and its password is a credential); the migration GRANTs to it and REFUSES to run if it is missing. They now run inside the same session-variable transaction. **Any future raw-SQL path must too.** (2) **Every request 401'd**: the auth bootstrap deliberately skips layer 1, but RLS fails closed, so unscoped reads on `ibms_app` returned nothing. Now scoped to the transaction's own async subtree. It failed CLOSED — the write was rejected, never misfiled. Measured cost +4ms / ~3.7x on a trivial query; explicit `$transaction` blocks pay it once. ## Before you write code

Same rule as ibms-brain: read `meta/context/` for the area, `meta/lex/` for what's
mandatory, cite the source document (PDPL / CBJ / ISO 27001/27701 / a specific
`PRIV-STD-*`/`PRIV-SOP-*`) in the PR when the change touches a regulatory obligation.
