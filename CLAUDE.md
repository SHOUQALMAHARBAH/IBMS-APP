the grants are per-office. The legacy 11 survive as ordinary per-office rows carrying
their old machine names, so nobody's access changed. An office now DEFINES its own roles
at `/settings/roles`, every office has an `OFFICE_ADMINISTRATOR`, and a new office gets
that role and nothing else.

Before touching anything role-related read **`docs/office-scoped-rbac.md`** — it
carries these four constraints in full, the things that will bite, and the Phase 4
hand-off:

1. **A role NAME is not an identity.** `PermissionRepository.findCodesForRoles` and
   `PermissionsService` both take ids, deliberately — a name-keyed lookup returns every
   same-named role across every office and hands the caller their union. The same
   applies at the API boundary: role assignment is id-addressed
   (`{ roleId }` / `{ roleIds }`), and the by-name repository lookups were deleted, not
   left dormant.
2. **An RLS policy is only enforceable on a model carrying `organizationId`**, because
   that is how `tenantScopeExtension` decides whether to set `app.current_org_id` at
   all. A policy on any other table matches nothing, forever.
3. **`Role.status` has to reach every query that DECIDES access**, not just the screen.
   A retired role that still satisfied the authorization read or the
   last-administrator count would keep granting everything it ever granted.
4. **`isSystem` grants nothing.** It stops the Role screen renaming, retiring or
   re-granting a row and is read nowhere else. A flag called "system" on a Role is
   exactly where an `if (isSystem) allow` bypass gets smuggled in; there is a test
   whose only job is to prove it does not exist.

Phases 4 and 5 (the unified screen's org-structure half, subdomain resolution, the
business-function routing table that retires the two remaining role-name sites; then
migration rehearsal and dropping the `RoleName` enum type) are not built.

**Insurer CRUD HAS shipped** — API and screens, with `insurer.create`, `insurer.update`, `insurer.deactivate`,
`insurer.read`, `insurer.directory.read` and `insurer.office-form.map` granted. **CORRECTED 2026-10-19: this said `insurer.relationship.manage`, WHICH DOES NOT EXIST** — Phase 1 split that umbrella five ways because it gated two ENTITIES (an office's insurer records and the insurance LINES those records carry), and the sentence was never updated. Anybody handed this file would have gone looking for a code that is not in the graph. This
paragraph said it was "deliberately deferred" for the whole branch that built it, which
is the doc rot `meta/lex/definition-of-done.md` names: a deferral is true when written
and nobody revisits it. What survives of that deferral is the property it protected —
those codes sit OUTSIDE the office administrator's strict-subset-at-migration set and are
listed explicitly in `ADDED_AFTER_THE_MIGRATION`, so a fifth cannot slip in without a
decision.

**Before touching anything insurer-related read `docs/insurer-management.md`** — the
eleven constraints in full, including the two that are easiest to break by accident: the
canonical name key lives in the DATABASE and the TypeScript mirror is for suggestions
only, and an insurer row holds two kinds of fact where only the company-level half may
ever leave the office. Its two siblings go deeper on the global catalogue
(`docs/insurer-master-registry.md`) and the cross-office directory
(`docs/insurer-directory.md`).

**Every screen is held to `docs/frontend-ux-directive.md`** — the owner's standing frontend and UX
instruction, in the repo because it reached one session as a message and the next would not have seen
it. Read it before building a screen. Its four-state requirement, its rule that a control a role
cannot use does not exist on their screen, and its reservation of implementation detail to the
System/Security Administrator are the three that change code most often. **It overlaps
`docs/b7-consistency-record.md` and disagrees with it in four places** — the header of the directive
states which, and those four are the owner's to settle, not to merge.

**Handing the system to someone who does not read code: `docs/first-run.md`** — the
bilingual (AR-first) first-sign-in walkthrough, walked against a running stack rather than
written from the source. It carries the measured per-account permission table, so if the
seed's role grants move, re-measure it rather than editing it by hand.
