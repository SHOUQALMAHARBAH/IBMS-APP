# CLAUDE.md — ibms-app

This is the first IBMS engineering repo. **Standards, mandatory rules, domain
knowledge, and architecture decisions live in `ibms-brain` (imported above via git
submodule at `ibms-brain/`), not here** — `ibms-brain/meta/lex/` (mandatory),
`ibms-brain/meta/context/` (domain knowledge), `ibms-brain/meta/designs/` (why decisions
were made). Read the relevant `meta/context/` file before touching an area, and the
`meta/lex/` rules before any non-trivial change — most of them (money-decimal-jod,
workflow-state-transitions, maker-checker-segregation, sensitive-data-handling,
pdpl-sla-timers) apply the moment real domain code lands here, which it has not yet.

| 2026-09-16 | **The five lists that grow without bound get pages — and two of the five turned out to have nothing to paginate.** Offset, not cursor: these screens are browsed by a person who wants page 3, the queries already order `createdAt desc`, and a cursor is the right answer for an export or an infinite scroll, neither of which exists here. One shared `common/pagination.ts` (`pageWindow` clamps to **50 default / 200 max**; a negative page, a zero size and `?pageSize=100000` are all **absorbed, never 422'd** — a refusal would only move the clamping into the client) and one shared `components/ui/Pagination.tsx`, so the lists behave identically. **Three of the five had a book-wide list to page.** `/customers` was genuinely unbounded. **`/policies` and `/audit-trail` were already capped** — at 200 and **5,000** rows — and the policy repository's own comment said why: "this codebase has no offset-pagination convention (0 of 50 list DTOs carry a page param)". That is the convention this adds, so both caps became windows and both comments were rewritten rather than left contradicting the code. The audit-log cap was the worse of the two: it answered a browse of an aged log by dropping everything past the newest 5,000 rows, and **the reader could not tell a short result from a truncated one**. `warnIfTruncated` is no longer called on that path — nothing is truncated, and `total` says how much there is; the two history reads still cap and still warn. **The other two had no book-wide endpoint at all**: `GET /claims` **422s** without exactly one of `policyId`/`customerId` and has **no list screen in the app**; `GET /invoices` **400s** without a scope and its own error text names the book-wide view as the Process 33 ageing report. Neither got a control — the honest options were a control that can never render, or two new endpoints and a new access-control surface. Recorded in README § Known gaps rather than quietly counted as done. **The response shape is uniform across every branch**, including the scoped ones (`wholeSet()` reports a bounded read as one complete page), so the client has one type per endpoint instead of one per branch — and `listPoliciesForOpportunity` unwraps it, leaving its five component callers untouched. Page and count run on **one shared `where`** in each repository, so "of N" can never contradict the rows on screen. **The security work was in the tests, not the code.** `tenant-isolation.e2e-spec.ts` proved isolation by scanning the returned rows for the other office's customer — under paging that only proves absence from page 0. Its list test now compares `total` against a raw count of office A's own rows (**one assertion covering every page**, and it caught that this caller actually sees **9,795**, so the single-page guard I first wrote was wrong); its search test **sweeps every page**, bounded by a constant, because db-test is cumulative and both offices add a row with that name every run. `policy.e2e-spec.ts`'s owner-visibility test got the same treatment, with the whole-book Checking Officer case deliberately exempted. **Verification**: typecheck 6/6, lint 3/3, build 3/3; unit **api 2940 · web 69 · db 24**; **api e2e 74/74 files, 492 tests, 0 failures** (five foreground batches); **`npm run test:a11y` 68/68**; web e2e **347/347 (+12)**. 12 screenshots, light/dark × EN/AR across all three screens. | **`?pageSize=` is clamped, not trusted** — `MAX_PAGE_SIZE` is the whole point of the module; a list endpoint that takes a caller's page size without a ceiling still has the unbounded query. **Under pagination, `expect(ids).not.toContain(x)` stops being a visibility proof** — it only speaks for the page it read. Assert against `total`, or sweep every page with a constant bound; never bound the loop by the response alone. **A repository comment explaining why something is capped is a thing to rewrite, not route around**, the day the reason stops holding. **The scoped branches return the paged envelope too** — do not "simplify" one back to a bare array; one response shape per endpoint is what lets `Pagination.tsx` stay a single component. **Not every list named in a pagination task has a list to paginate** — check for the book-wide branch before building; `/claims` and `/invoices` did not have one, and inventing one is a new access-control surface, not a capping fix. |
| 2026-09-16 | **Trusted devices become visible — and the endpoint stopped handing the browser a movement log.** `GET /auth/trusted-devices` and its revoke have existed since Part II §4.4 with **no UI at all**: a password change revoked every trusted device server-side, but nobody could look at the list, spot a machine they did not recognise, and drop it. The audit flagged it; this closes it, on `/settings/security` beside MFA and the password change. **The find while building it**: `list()` returned the whole `TrustedDevice` ROW, including **`deviceFingerprintHash` and `firstSeenIp`**. The same file refuses to put a device identifier in the audit trail — its own comment says one "becomes a movement log for the employee" — and a JSON response the browser can read is no better a place for it. `list()` now returns a view of `id` / `label` / `trustedAt` / `expiresAt` / `lastUsedAt`; nothing consumed the wider shape, so narrowing cost nothing. An api e2e assertion pins the exact key set AND asserts neither field appears anywhere in the payload. **Two lint rules caught real mistakes, not style**: the hooks were first placed AFTER this page's `if (isLoading || !user) return null`, which `rules-of-hooks` rejects; and `set-state-in-effect` still flagged the loader with an `await` in it, because the rule traces into the callee. Restructuring to `.then()` with a `cancelled` flag satisfied both and **closed an unmount race** — navigating away mid-request would have set state on a dead page. Revoke **re-reads** rather than splicing the row out, so a device whose trust lapsed while the page was open disappears on the same refresh. **Verification**: typecheck 6/6, lint 3/3, build 3/3; unit api 2933 · web 69 · db 24; `auth-mfa-session` e2e 25/25; a11y 68/68; web e2e **333/333 (+3)**. | **Never return a whole Prisma row from an auth endpoint** — `TrustedDevice` carried a stable device identifier, and the only reason it was not a leak in practice is that nothing rendered it. Map to a view. **A per-item action needs a per-item accessible name**: the revoke buttons are labelled "Revoke trust for {device}", because five identical "Revoke"s tell a screen-reader user nothing about which one they are pressing. **`set-state-in-effect` traces into what the effect CALLS** — an `await` inside a helper does not satisfy it; set state in a `.then()` callback, and take the cancellation flag while you are there. **Still no UI, still logged**: email integration, insurer master data, SLA timer control and its holiday calendar, screening case workflow, refund disbursement — all deferred post-launch by the client, see the audit. |

The link was one-directional (Employee -> User), not missing. Provisioning now carries the other direction, which matches the real sequence: HR record first, account second. **(3) `linkUser` enforces a DEPARTMENT-AGREEMENT rule** — an account cannot link to an employee in another department — and the new provisioning path bypassed it until it was mirrored. A rule enforced on one of two paths is not a rule. **(4) Link-only, never create.** An `Employee` requires a national ID, Highly Confidential under Part 10.2, and an account-provisioning form is not where that should first be typed. **Neither direction was reachable from the UI** — the employees form never sent `userId`, the users form had no `employeeId` — so the create-user form gained one picker, gated on `employee.manage` because a select that 403s on load is worse than no select. **Verification**: typecheck 6/6, lint 3/3, build 3/3; unit **api 2933 (+4) · web 69 · db 24**; `auth-mfa-session` e2e **25/25 (+2)** — the link, the refusals (unknown 422 / already-taken 409 / department mismatch 409) and the unlinked fallback; a11y 68/68; web e2e 330/330. | **`Employee.fullName` is the display name wherever an account is linked** — use `resolveDisplayName()`, never `user.fullName` directly, in anything a person reads. Audit entries are the documented exception. **Linking is reachable BOTH ways and both must stay in step**: `POST /employees` with `userId`, and `POST /admin/users` with `employeeId`. A rule added to one — the department-agreement check is the existing example — belongs on the other the same day. **Never create an Employee from an account form**: it needs a national ID. **No `/settings/profile` page was built, and that is the finished state, not a gap** — the navbar dropdown already shows the official name and department, `/settings/security` already owns the password, the name is read-only by client ruling, and a page that only restates what is two feet above it is what directive §4 forbids. **A grep for an assignment is not a search for a writer** — the audit's missing-link finding was wrong because the write was a repository method, and that class of mistake is worth one extra check before reporting an absence. |

The mapping was **computed**, each literal composited over the light card and matched to the nearest token (0.15/0.2 -> `--border-subtle`, 0.25/0.3 -> `--border-default`, 0.4 -> `--border-strong`). The count came out above the 110 estimated because the first pass matched **single-quoted declarations only**; six more were written with double quotes. **Verified by pixel diff, not assertion** — the sweep stashed, the app rebuilt, the same pages captured with POPULATED fixtures: **worst page 0.167% of pixels, max channel delta 4/255**. ## Environment

mandatory, cite the source document (PDPL / CBJ / ISO 27001/27701 / a specific
`PRIV-STD-*`/`PRIV-SOP-*`) in the PR when the change touches a regulatory obligation.
