# CLAUDE.md — ibms-app

This is the first IBMS engineering repo. **Standards, mandatory rules, domain
knowledge, and architecture decisions live in `ibms-brain` (imported above via git
submodule at `ibms-brain/`), not here** — `ibms-brain/meta/lex/` (mandatory),
`ibms-brain/meta/context/` (domain knowledge), `ibms-brain/meta/designs/` (why decisions
were made). Read the relevant `meta/context/` file before touching an area, and the
`meta/lex/` rules before any non-trivial change — most of them (money-decimal-jod,
workflow-state-transitions, maker-checker-segregation, sensitive-data-handling,
pdpl-sla-timers) apply the moment real domain code lands here, which it has not yet.

| 2026-09-17 | **`PENDING_KYC` stops reaching the screen: 57 raw enum renders now read a label, in both languages.** **Guessing did not work and was abandoned.** Matching a field to its vocabulary by NAME resolved 31 of 60 and produced candidate lists nineteen entries long — `status` exists on nineteen interfaces. The answer was to ask the TypeScript compiler: a script walks the AST for a JSX expression that is a bare property access and asks the checker what it resolves to. **57 sites, 34 vocabularies, 202 values, zero unresolved.** For the 29 fields the web layer typed as bare `string`, the checker still gave the OWNING interface, which pinned the vocabulary to a Prisma enum, a schema comment documenting the allowed values, or an `as const` in the api's own config — traced one at a time, never guessed. **Those 29 fields were tightened to real unions, and that is load-bearing, not tidying**: `ENUM_LABEL.X` is a literal-keyed object, so indexing it with `string` does not compile. The union is what makes the lookup type-check AND what makes the map exhaustive — add a value to a vocabulary without a label and the build fails, where before the screen quietly printed the code. All 29 tightened with **zero ripple**. **44 values already had a purpose-built key; 123 were written.** A key is reused only when its NAME says it belongs to the vocabulary (`incStatusContained`), never because its English happens to match — `ClaimStatus.APPROVED` is not `kycStatusApproved`, and coupling them breaks the day KYC rewords its own label. **Eight vocabularies already had a complete working map that another screen ignored** (`PolicyStatus`, `CustomerStatus`, `LeadSource`, `DeliveryMethod` among them). **The rewrite introduced a real defect and the tests caught it**: it replaced every matching JSX expression, including seven inside `data-*` and `value=` ATTRIBUTES — turning machine hooks into translated labels and breaking `[data-status="HEALTHY"]` selectors. | 2026-09-16 | **The five lists that grow without bound get pages — and two of the five turned out to have nothing to paginate.** Offset, not cursor: these screens are browsed by a person who wants page 3, the queries already order `createdAt desc`, and a cursor is the right answer for an export or an infinite scroll, neither of which exists here. One shared `common/pagination.ts` (`pageWindow` clamps to **50 default / 200 max**; a negative page, a zero size and `?pageSize=100000` are all **absorbed, never 422'd** — a refusal would only move the clamping into the client) and one shared `components/ui/Pagination.tsx`, so the lists behave identically. **Three of the five had a book-wide list to page.** `/customers` was genuinely unbounded. **`/policies` and `/audit-trail` were already capped** — at 200 and **5,000** rows — and the policy repository's own comment said why: "this codebase has no offset-pagination convention (0 of 50 list DTOs carry a page param)". That is the convention this adds, so both caps became windows and both comments were rewritten rather than left contradicting the code. The audit-log cap was the worse of the two: it answered a browse of an aged log by dropping everything past the newest 5,000 rows, and **the reader could not tell a short result from a truncated one**. `warnIfTruncated` is no longer called on that path — nothing is truncated, and `total` says how much there is; the two history reads still cap and still warn. **The other two had no book-wide endpoint at all**: `GET /claims` **422s** without exactly one of `policyId`/`customerId` and has **no list screen in the app**; `GET /invoices` **400s** without a scope and its own error text names the book-wide view as the Process 33 ageing report. Neither got a control — the honest options were a control that can never render, or two new endpoints and a new access-control surface. Recorded in README § Known gaps rather than quietly counted as done. **The response shape is uniform across every branch**, including the scoped ones (`wholeSet()` reports a bounded read as one complete page), so the client has one type per endpoint instead of one per branch — and `listPoliciesForOpportunity` unwraps it, leaving its five component callers untouched. Page and count run on **one shared `where`** in each repository, so "of N" can never contradict the rows on screen. **The security work was in the tests, not the code.** `tenant-isolation.e2e-spec.ts` proved isolation by scanning the returned rows for the other office's customer — under paging that only proves absence from page 0. Its list test now compares `total` against a raw count of office A's own rows (**one assertion covering every page**, and it caught that this caller actually sees **9,795**, so the single-page guard I first wrote was wrong); its search test **sweeps every page**, bounded by a constant, because db-test is cumulative and both offices add a row with that name every run. `policy.e2e-spec.ts`'s owner-visibility test got the same treatment, with the whole-book Checking Officer case deliberately exempted. **CI then failed the one thing five local batches could not catch — and it was a real defect, not a flake.** `/audit-trail` is the one list whose own reads APPEND to the table they read: every browse records a PDPL access row, which sorts straight to the top under `occurredAt desc` and shifts every later page down by one. So clicking Next re-showed a row page 0 had already shown, and hid another entirely. It passed locally three times and failed in CI, which is exactly the shape of a race that is really an ordering bug. The fix is in the UI, not just the test: the browse **pins `to` to the instant it was submitted** and reuses it for every page, so an audit browse reads "as at the moment you searched" — which is the more honest thing for it to mean anyway. The e2e pins the same instant and now asserts the two pages are disjoint AND that `total` is identical rather than merely non-shrinking. 3/3 consecutive local runs. **Verification**: typecheck 6/6, lint 3/3, build 3/3; unit **api 2940 · web 69 · db 24**; **api e2e 74/74 files, 492 tests** (CI's own count, 491 pass + the 1 now fixed); **`npm run test:a11y` 68/68**; web e2e **347/347 (+12)**. 12 screenshots, light/dark × EN/AR across all three screens. | **`?pageSize=` is clamped, not trusted** — `MAX_PAGE_SIZE` is the whole point of the module; a list endpoint that takes a caller's page size without a ceiling still has the unbounded query. **Under pagination, `expect(ids).not.toContain(x)` stops being a visibility proof** — it only speaks for the page it read. Assert against `total`, or sweep every page with a constant bound; never bound the loop by the response alone. **A repository comment explaining why something is capped is a thing to rewrite, not route around**, the day the reason stops holding. **The scoped branches return the paged envelope too** — do not "simplify" one back to a bare array; one response shape per endpoint is what lets `Pagination.tsx` stay a single component. **Offset paging is unstable over a table the endpoint itself writes to** — `/audit-trail` records a row per read, so an unpinned second page repeats a row. Pin the window (`to`) for the whole browse; and note that five green local batches did NOT catch it while CI did. **Not every list named in a pagination task has a list to paginate** — check for the book-wide branch before building; `/claims` and `/invoices` did not have one, and inventing one is a new access-control surface, not a capping fix. |

## Before you write code

Same rule as ibms-brain: read `meta/context/` for the area, `meta/lex/` for what's
mandatory, cite the source document (PDPL / CBJ / ISO 27001/27701 / a specific
`PRIV-STD-*`/`PRIV-SOP-*`) in the PR when the change touches a regulatory obligation.
