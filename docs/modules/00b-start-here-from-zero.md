# 🔹 المرحلة ٠ — **قبل أن تلمس كوداً**

**١ · اقبل دعوةَ GitHub** من بريدك.

**٢ · نزّل `Node 20`.** **المطلوبُ مقيسٌ من `package.json`: `"node": ">=20.19.0"`** — **فأيُّ نسخةٍ من ٢٠ من ١٩ وطالع تمشي** (٢٠٬٢٠٬٢ مثلاً تمشي). **و`.nvmrc` يحمل `20.19.0` وهي النسخةُ التي يشغّلها الفحصُ الآليُّ بالذات** (`node-version-file: ".nvmrc"`)، **فلو عندك `nvm` شغّل `nvm use` داخلَ المجلّدِ لتصير مطابقاً للفحصِ تماماً.**

**٣ · نزّل `Docker Desktop` وشغّله**، وتأكّد أنّه شغّالٌ فعلاً — لا أنّ أيقونتَه موجودة.

> ## ⚠ وتنبيهٌ تراه عند `npm install` — **اقرأه ولا تتصرّف عليه**
>
> **`npm warn EBADENGINE … vitest@5.0.3 … required: node ^22.12.0 …`**
>
> **هذا تنبيهٌ حقيقيٌّ ومقيس:** `vitest@^5.0.3` **تعريفُ محرّكِه يطلب `Node 22` وطالع**، وهو مُعلَنٌ مباشرةً في ثلاثِ مساحاتِ عملٍ (`apps/api` · `apps/web` · `packages/db`). **و`.nvmrc` يقول ٢٠٬١٩٬٠، والفحصُ الآليُّ يقرأ `.nvmrc`.** ⟶ **فالفحصُ نفسُه يشغّل `vitest 5` على `Node 20`.**
>
> **ومقيسٌ أنّه يمشي:** آخرُ تشغيلٍ كامل — **٢٨٣ ملفَّ اختبارٍ و٣٦٢٨ اختباراً في الخادم · ١٦٠ في قاعدةِ البيانات · ١٩٩ في الواجهة — كلُّها نجحَت على `Node 20`.** **فتعريفُ المحرّكِ أضيقُ من الواقعِ، لا أنّ عندنا عطباً.**
>
> **⟶ فالتنبيهُ يُسجَّل ولا يُعالَج هنا.** **ولا تُرقّي `Node` ولا `vitest` لتُسكِته** — **فترقيةٌ تُسكِت تنبيهاً وتُخرجك عن نسخةِ الفحصِ تُنتج «يمشي عندي ويفشل في الفحص»، وهو أسوأُ من التنبيه.** *(وهذا تناقضٌ مسجَّلٌ في المستودعِ ليُحسَم في مكانٍ واحد، لا على جهازِ كلِّ واحد.)*
>
> ## ⛔ وأمرٌ لا تشغّله، مهما قال لك `npm` أن تشغّله
>
> **`npm audit fix` و`npm audit fix --force`.**
>
> `npm install` ينتهي بسطرٍ يقول **«25 vulnerabilities»** ويعرض عليك الأمرَين. **⛔ لا تشغّل أيّاً منهما.** ⟶ **`--force` يرفع نسخاً رئيسيةً ويكسر البناءَ، و`fix` العادي يغيّر قفلَ الحزمِ فيصير قفلُك مختلفاً عن قفلِ الفريقِ وقفلِ الفحص.**
>
> **وللمستودعِ سياستُه المعلَنةُ لهذا أصلاً:** `npm run test:security` ← `scripts/audit-check.mjs`. **فالتدقيقُ يُقرَأ من هناك، لا من سطرِ `npm`.** **ومن وجد ثغرةً تستاهل، يبلّغ ولا يُصلِح على جهازِه.**

# 🔹 المرحلة ١ — **انسخ المستودعَ ومعه الدماغ**

```bash
git clone --recurse-submodules https://github.com/SHOUQALMAHARBAH/IBMS-APP.git
cd IBMS-APP
```

> ## ⛔ `--recurse-submodules` ليست اختيارية
>
> **بدونها ينزل المستودعُ بلا مجلّد `ibms-brain`** — **وهو «الدماغ»: القوانينُ الداخليةُ وفهرسُ القراراتِ والسياقُ التجاريّ.** **ونصفُ الوثائقِ تُحيل إليه، فتقرأ إحالةً إلى ملفٍّ غيرِ موجودٍ عندك وتحسب أنّ الوثيقةَ غلط.**
>
> **ونسيتَها؟** `git submodule update --init --recursive`

**وتأكّد أنّك على `main`:**

```bash
git branch --show-current     # لازم يطلع: main
```

**⛔ ولا تشتغل على فرعٍ آخرَ من القدام.** `main` هو آخرُ نسخةٍ من كلِّ شي.

# 🔹 المرحلة ٢ — **مفاتيحُك والحزمُ وعميلُ قاعدةِ البيانات**

> ## ✅ **هذا التسلسلُ مُشيَ من الصفرِ على جهازٍ حقيقيٍّ في ٨ تشرين الثاني، وكلُّ سطرٍ فيه نجح.**
> **وصُحِّح فيه ثلاثةُ أشياءَ كانت تُوقِف النسخةَ الجديدةَ ميتاً.** ⟶ **امشِ الأسطرَ كما هي وبترتيبِها.**

```bash
cp .env.example .env
cp .env.test.example .env.test

npm install

npm run db:generate
```

## 🔴 `npm run db:generate` — **الخطوةُ التي كانت ناقصةً، وبلاها يفشل كلُّ ما بعدها**

**`npm install` لا يولّد عميلَ Prisma.** **ومقيس: ما في `postinstall` ولا `prepare` في أيِّ `package.json` في المستودع.**

⟶ **فلو تخطّيتَها، أوّلُ أمرٍ يستورد `@prisma/client` يسقط برسالةٍ تقول:**
`@prisma/client did not initialize yet. Please run "prisma generate"`
**وهي رسالةٌ لا تشير إلى الخطوةِ الناقصةِ في تسلسلِك، فتقعد تبحث في الإعدادِ وهي خطوةٌ لم تُشغَّل.**

**والأوامرُ التي تحتاجها:** `db:provision-app-role` · `db:seed` · `npm run dev` · والاختبارات. **يعني كلُّ شي.**

# 🔹 المرحلة ٣ — 🔴 **قاعدةُ البيانات**

```bash
docker compose up -d db
```

## 🔴 السطرُ الأوّلُ الخطر — `db:provision-app-role`

**اكتبه بهذا الشكلِ بالضبط. سطرٌ واحدٌ منطقيٌّ، والشرطةُ المائلةُ في آخرِ السطرِ الأوّلِ جزءٌ منه:**

```bash
DATABASE_URL="$(grep -m1 '^DATABASE_URL=' .env | cut -d= -f2-)" APP_DB_PASSWORD='الكلمةُ-من-APP_DATABASE_URL' npm run db:provision-app-role
```

**ونجاحُه يُعرَف من ثلاثةِ أسطرٍ يطبعها:**
```
Role "ibms_app" already existed — password updated.        (أو: created)
"ibms_app" is a plain login role: no superuser, no BYPASSRLS, owns nothing.
Next: run the migrations (they GRANT to it and create the policies)
```

### ❓ وثلاثةُ أشياءَ تُسقِط الناسَ في هذا السطرِ وحدَه

**١ · ⛔ القوسانِ `< >` ليسا من الأمر.** هما علامةُ «املأ هنا» في الورقاتِ — **وفي `bash` هما إعادةُ توجيه**، فتطلع لك `bash: ibms: No such file or directory`. **اكتب القيمةَ بين علامتَي تنصيصٍ فرديّةٍ `'...'` بلا أقواسٍ مثلَّثة.**

**٢ · 🔴 ولازم تُمرِّر `DATABASE_URL` بنفسِك.** **مقيس: السكربتُ `node` مجرّدٌ بلا `dotenv`، فهو لا يقرأ `.env` إطلاقاً** — خلافاً لثمانيةِ سكربتاتٍ أخرى في نفسِ الملفِّ مكتوبةٍ `dotenv -e .env -- node ...`. ⟶ **وبدونها تطلع لك `neither ADMIN_DATABASE_URL nor DATABASE_URL is set`، وهي رسالةٌ عن بيئتِك لا عن إعدادِك.**

**٣ · ⛔ ولا تستعمل `set -a; source .env; set +a` هنا.** **جُرِّب وفشل:** في `Git Bash` على ويندوز **لا تُصدَّر القيمُ إلى الأمرِ الذي بعده** — تطلع أسطرٌ مثل `[1] Done DATABASE_URL=...` وتظنُّ أنّها نجحَت، **ثمّ يسقط الأمرُ بنفسِ رسالةِ البيئة.** *(والأرجحُ أنّ `.env` بنهاياتِ أسطرِ ويندوز. فحصٌ لا يكشف ولا قيمة: `tr -cd '\r' < .env | wc -c` — أكبرُ من صفرٍ يعني `CRLF`.)*

### وكلمةُ السرِّ: ما هي، ومن أين تأخذها

**هي كلمةُ سرِّ الدورِ `ibms_app`، وهو الدورُ الذي يتّصل به النظامُ الشغّال. تختارها أنت، وهي سرٌّ محليٌّ على جهازِك.**

**🔴 ولازم تكون نفسَ الكلمةِ الموجودةِ داخلَ `APP_DATABASE_URL` في `.env`.** ⟶ **السكربتُ ينشئ الدورَ بكلمةٍ، والنظامُ يتّصل بكلمةٍ من `.env`؛ ولو اختلفتا، التثبيتُ ينجح ثمّ يفشل الاتصالُ وقتَ التشغيلِ برسالةٍ عن المصادقةِ لا عن الإعداد.**

**وأبسطُ طريق:** **افتح `.env`، لقِّط `APP_DATABASE_URL`** — شكلُه `postgresql://المستخدم:كلمةُ-السرّ@المضيف:البورت/القاعدة` — **وخُذ المقطعَ بين `:` و`@`. استعمله كما هو، فما تحتاج تعدّل `.env` إطلاقاً.**

**والسكربتُ يُعاد تشغيلُه بلا ضرر:** إعادتُه **تُحدّث** كلمةَ السرِّ ولا تفشل.

**⛔ ولا تُرسِل كلمةَ السرِّ لأحدٍ ولا تكتبها في تقريرٍ ولا محادثة.**

## 🔴 السطرُ الثاني الخطر — **وهو أخطرُ سطرٍ في المستودعِ كلِّه**

```bash
npm run db:migrate:deploy
```

### **`deploy` — لا `dev`. ولا مرّةً `dev` على قاعدةِ التطوير.**

`npm run db:migrate:dev` **يُنزّل الـ١٦٤ ترحيلةً كلَّها صحيحة**، ثمّ **يسألك «اكتب اسماً للترحيلةِ الجديدة»** — لأنّ `schema.prisma` لا يقدر يعبّر عن أشياءَ تُنشئها الترحيلات، فيقرأها انحرافاً يلزم إلغاؤه.

**والترحيلةُ التي يعرض أن يكتبها تَحذف:**

| ما يُحذَف | العدد | الأثر |
|---|---|---|
| **مفاتيحُ أجنبية** | **١٦** — **خمسةَ عشرَ منها قيودُ `*_same_org_fkey`** | **القيودُ التي تمنع تسرُّبَ بياناتِ مكتبٍ لمكتبٍ آخر** |
| فهارسُ بحثٍ نصّيّ | ٣ | البحثُ يصير بطيئاً أو خاطئاً |
| أعمدةٌ محسوبة | ٦ | قيمٌ تُحسَب تلقائياً تتوقّف |

⟶ **تكتب اسماً وتضغط Enter، فيصير عزلُ المكاتبِ أضعفَ على جهازِك بالسكوت. ولا رسالةَ خطأٍ ولا تنبيه.**

**و`deploy` يُنزّل المعلَّقَ وبس:** لا يسأل، ولا يقارن بـ`schema.prisma` أبداً.

> **⚠ ورسالتانِ كلتاهما سليمة:** **`164 migrations found … applying`** على قاعدةٍ جديدةٍ فعلاً · **و`No pending migrations to apply`** لو كانت القاعدةُ قد هُيِّئَت قبلاً على نفسِ الجهاز. **فالثانيةُ ليست فشلاً.** ⟶ **والتحقُّقُ الحقيقيُّ هو `npm run db:seed` بعدها: إن طبعَ أسماءَ الجداولِ وأعدادَها، فالمخطَّطُ موجود.**

## وابذر البيانات

```bash
npm run db:seed
```

**بلاها ما في صلاحياتٌ إطلاقاً.** **ونجاحُه يُعرَف من أسطرٍ تحمل أعداداً، أهمُّها:**
**`Seeded 230 permissions`** · **`Seeded 32 standard insurance lines`** · **`Seeded 12 roles`** · **`Seeded 10 document template(s)`** · **`Seeded the PROVIDER organization and its PLATFORM_OPERATOR role (13 permissions)`**.

**وهو آمنٌ تماماً عند الإعادة:** **كلُّ سطرٍ يقول «already present — left unchanged» هو صحيحٌ لا عطل.** ⟶ **والبذرُ لا يَكتب فوقَ مُدَدِ الاحتفاظِ عند مكتبٍ ضبطَها، لأنّ «مدّةَ المكتبِ قرارُه هو».**

## وقاعدةُ الاختباراتِ — **منفصلةٌ تماماً**

```bash
docker compose up -d db-test
npm run db:test:migrate:deploy
npm run db:test:seed
```

**⛔ ولا أحدَ يجرّب تغييرَ مخطَّطٍ على `db`. كلُّ تجربةٍ تصير على `db-test` أوّلاً.** *(ولمّا تبلّش تغيّر المخطَّطَ فعلاً، الأمرُ `npm run db:test:migrate:dev` — هذي وظيفتُه، وعلى قاعدةِ الاختباراتِ وحدَها.)*

> ## ⚠ تحقُّقٌ يستاهل أن تعمله مرّةً — **قصّةٌ حقيقية**
>
> **`db` اسمُها `ibms` على بورت 5433 · و`db-test` اسمُها `ibms_test` على 5434.** **وتراهما في خرجِ الأمرَين فوق، فتأكّد أنّ كلَّ واحدٍ ذهب لقاعدتِه.**
>
> **في يومٍ رجعَت الحاويتانِ من تلقاءِ نفسِهما بالبورتَينِ متقاطعَين.** **والذي أنقذ الموقفَ أنّ الاسمَين مختلفان، فكلُّ اتصالٍ فشل فوراً بـ`Database "ibms" does not exist`.** ⟶ **ولو كانا بنفسِ الاسم، كانت اختباراتُ الـe2e اشتغلَت على قاعدةِ التطويرِ ونجحَت وكتبَت فوقَ بياناتِها — ولا شيءَ في الاختباراتِ يعرف إلى أيِّ قاعدةٍ وصل.**
>
> **فـ«نبسّطهما لنفسِ الاسم» تعديلٌ يبدو ترتيباً، وهو يُزيل الحمايةَ الوحيدةَ من هذا.** **والإصلاحُ لو تقاطعا:** `docker compose restart db db-test`.

> **والسببُ واحدٌ في الخمسة:** **الفحصُ الآليُّ يشغّل نسخاً مثبَّتة** (`node-version-file: ".nvmrc"` وقفلُ الحزم). ⟶ **فترقيةٌ على جهازِك تُنتج «يمشي عندي ويفشل في الفحص»، وهذي أسوأُ حالةٍ ممكنة: ما حدَ يقدر يعيد إنتاجَ عطبِك ولا إنتاجَ نجاحِك.**

> **ومن وجد ترقيةً تستاهل فعلاً: يبلّغ، ولا يُرقّي على جهازِه.**

# 🔹 المرحلة ٦ — 🔴 **قِس مديولَك قبل أوّلِ سطرِ كود**

**ما أحدَ يكتب سطراً قبل أن ينشر «شو موجودٌ وشو ناقص» مقيساً من الكود.** **والقياسُ هو تسليمُك الأوّل.**

**بدّل `customer` باسمِ مديولِك:**

```bash
# ١ — كم جدولاً في النظامِ كلِّه
grep -c "^model " packages/db/prisma/schema.prisma                    # → ١٦١

# ٢ — كم مساراً مبنيٌّ في مديولك
grep -c "@Get(\|@Post(\|@Patch(\|@Delete(" \
  apps/api/src/modules/customer/customer.controller.ts

# ٣ — شو الشاشاتُ التي إلها علاقة
ls "apps/web/app/(app)" | grep -i customer

# ٤ — كم صلاحيةً تحرسه
grep -c 'code: "customer' packages/db/prisma/seed-data/permissions.ts

# ٥ — شو الاختباراتُ التي تحرسه
ls apps/api/test/ | grep -i customer

# ٦ — في مساراتٌ مبنيّةٌ وما أحدَ يناديها؟
npm run check:unreachable-routes
```

> **⚠ وتحذيرٌ على الأمرِ السادس:** **هذي الأداةُ تعدُّ ذكرَ المسارِ وصولاً، لا نداءً فعلياً** — **فأرقامُها أرضيةٌ لا حقيقة.** **انكشفَت لمّا طلع أنّ المكتبَ لا يقدر يعدّل سجلَّ شركةِ تأمينٍ إطلاقاً والأداةُ تقول إنّه موصول.** ⟶ **اقرأ نتيجتَها، ولا تثق فيها.**

**ثمّ انشر القياسَ بقالبِ «فتحِ مديول»** — القالبُ في `00a-day-one-setup-and-verification.md`, القسمُ ٥.

# ⛔ وثلاثُ ممنوعاتٍ ما إلها استثناء — **في أيِّ مديولٍ وفي أيِّ وقت**

**١ · ما أحدَ يأخذ صلاحيةً عشان شاشةٌ تشتغل.** **الشاشةُ ما اشتغلَت؟ افهم ليش ممنوع، لا تفتح البابَ.** ⟶ **وهذا نظامٌ محكومٌ برقابة: صلاحيةٌ تُمنَح لتعمل شاشةٌ تبقى ممنوحةً بعدها لكلِّ من يحمل الدور.**

**٢ · ولا كلمةٌ عربيةٌ تُخترَع.** **تُقَصُّ من نصٍّ شغّالٍ في المستودعِ، أو تكون من الإدارة. ثالثَ ما في.**
```bash
grep -rn "الكلمة" apps/web/lib/i18n/translations/
```
*(آخرُ مرّة: ١٠ من ١١ كلمةً كانت موجودةً أصلاً. ومرّةً ثانية: كلمةٌ كان ناقصَها تصريفٌ — **والتصريفُ نفسُه قرارُ الإدارةِ لا قرارُك.**)*

**٣ · ولا أحدَ يَلمس `.env`. ولا أحد.**
