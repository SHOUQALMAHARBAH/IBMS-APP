PERMISSION CATALOGUE — the Arabic one-line descriptions, as the Role screen renders them

219 permission codes, 12 modules. Generated by
`npm run db:permission-descriptions` from the seeded catalogue AND from the Arabic text in
`apps/web/lib/i18n/translations/permissions.ts`, so this IS what the Role screen renders.

DO NOT WRITE IN THIS FILE. It is a mirror for reading. The Arabic lives in the dictionary with
every other user-facing string in the system, which is what keeps one home and one set of guards
rather than two copies that drift. A line typed in here is REFUSED by
`npm run db:permission-descriptions:check`, which names the code and where the line belongs —
it is never silently overwritten.

HOW TO READ THIS
  [5-STATE]  A CRUD-shaped family. The screen shows it as ONE row with its states side by side,
             and its member codes are indented beneath it here. A description is still wanted per
             CODE, because each state means something different to a person.
  [toggle]   A single on/off permission. One description.

WHAT IS WANTED: one short line per code, in Arabic, saying what holding it ALLOWS — what the
person can then do on screen. Not the code restated.

The "en:" line is the description already stored in the database. It is developer-facing and
often terse: a hint, not something to translate.

EVERY code has a line, with no exemptions — including the three whose en: line begins NOT YET
ENFORCED. Those three carry a line saying exactly that: holding one does nothing today. An
exemption list is how a gap stops being counted, so there is none, and the guard is fail-on-any.
